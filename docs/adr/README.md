# Architecture Decision Records (ADRs)

Use this directory for decisions with lasting consequences. Do not create an ADR for every small implementation choice.

Good candidates include persistence strategy, AI-provider integration, the shared relationship model, GUI approach, report-schema compatibility, and public Python API stability.

## Filename

`NNNN-short-decision-title.md`, for example `0001-analysis-results-persistence.md`.

## Template

```markdown
# ADR NNNN: Decision title

- Status: Proposed | Accepted | Superseded | Rejected
- Date: YYYY-MM-DD
- Decision owners: ...

## Context
What requirement or problem forces a decision?

## Decision
What are we choosing?

## Alternatives considered
What credible options were considered?

## Consequences
Benefits, costs, risks, migration needs, and reversibility.

## Verification
How will we confirm the decision works?
```

Keep decisions concise. Mark proposals Proposed until explicitly accepted.
